# Contributing

Thanks for taking the time to contribute. Bug reports, questions, and pull requests are
all welcome.

## Reporting issues

Open an issue at
<https://github.com/Data-JT/puppet-proxmox_virtual_environment/issues>. Please include:

- The module, Puppet, and PVE versions in use.
- What you expected to happen and what happened instead.
- A minimal manifest or Hiera snippet that reproduces the problem, with secrets redacted.
- Relevant Puppet output (`puppet agent -t --debug` is often helpful).

Do not include API tokens, passwords, certificates, real hostnames, or other production
data in issues, tests, commits, or logs. For security-sensitive reports, follow
[SECURITY.md](SECURITY.md) instead of opening a public issue.

## Development setup

The module uses the [PDK](https://www.puppet.com/docs/pdk). Run `script/setup-git-hooks`
once after cloning: the pre-commit hook regenerates and stages `REFERENCE.md` from the
source documentation. Then run the checks:

```sh
pdk test unit                              # unit tests
pdk validate                               # puppet-lint, rubocop, metadata, and syntax checks
pdk bundle exec rake spec:simplecov        # unit tests with line coverage
pdk bundle exec rake reek                  # Ruby smell detection
pdk bundle exec rake quality:rubocop       # RuboCop against the zero-offense baseline
```

The `Quality` and `Documentation` GitHub Actions workflows run these checks on every pull
request, including a 90% minimum line-coverage gate.

## Pull requests

- Add or update specs for any behavior change; new resource attributes and providers are
  expected to ship with unit tests.
- Keep providers convergent and never return or log secrets.
- Regenerate and validate the reference documentation after changing a public interface;
  see [Reference documentation](#reference-documentation).
- Add a `CHANGELOG.md` entry under the unreleased section describing your change.

## Reference documentation

`REFERENCE.md` is generated by Puppet Strings from comments and descriptions in the module
source; update those source descriptions instead of editing `REFERENCE.md` directly.
Regenerate it after changing a public interface or its documentation, and validate that the
committed copy is current:

```sh
bundle exec rake strings:generate:reference
bundle exec rake strings:validate:reference
```

When developing through PDK, prefix either command with `pdk`. The `Documentation` workflow
runs `strings:validate:reference` and fails when the committed reference differs from the
generated output.

User documentation beyond the reference lives in `docs/`; the README links to it with absolute
GitHub URLs, because the Forge does not resolve relative links.

## Design notes

The [PVE API viewer](https://pve.proxmox.com/pve-docs/api-viewer/) is the source of truth for endpoints and schemas.
Convergent configuration is modeled as `pve_*` Resource API types; one-off operations
stay in the generic `pve_api_request` task rather than becoming resources.
